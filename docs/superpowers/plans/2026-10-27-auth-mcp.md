# Auth rewrite, MCP server and secret links — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace go-pkgz/auth with econumo's opaque-token auth stack (sessions, PATs, Google/Apple/OIDC, OAuth 2.1 server for MCP clients), then add a stateless `/mcp` endpoint with the Docker-app deploy-loop tools and secret links.

**Architecture:** Port econumo's `internal/infra/auth` (argon2id), `internal/oauth` (Winterflow as OAuth client), `internal/authserver` (Winterflow as OAuth server) and `internal/web/mcp` into Winterflow's hexagonal layout (domain usecases in `internal/domain/usecase/...`, sqlc repositories in `internal/infra/db/repository/...`, HTTP in `internal/app/web/...`). One `access_tokens` table backs every credential; one auth middleware resolves cookie/Bearer/Basic to a user id kept in the request context, read through the unchanged `webutil.GetUserID(r)`. MCP tools call the same usecases as REST handlers and wait (≤ 50 s) on persisted command results.

**Tech Stack:** Go 1.27, chi, sqlc (SQLite + Postgres), `github.com/modelcontextprotocol/go-sdk` (same version as econumo, v1.8.0), `golang.org/x/crypto/argon2`, `golang.org/x/oauth2`; React 19 + Vite + vitest in `web/`.

**Spec:** `docs/superpowers/specs/2026-10-26-auth-mcp-design.md` (read it first). Reference implementation: econumo, cloned at `/tmp/eco` (if missing: `git clone --depth 1 https://github.com/econumo/econumo /tmp/eco`). Read econumo's `docs/superpowers/specs/2026-07-10-opaque-tokens-sessions-design.md`, `2026-09-07-oauth-login-design.md`, `2026-10-03-mcp-oauth-design.md`, `2026-07-11-mcp-server-design.md` for the task you're on. Where econumo and the spec differ, the spec wins; where the spec and this plan differ, this plan's pinned names win.

## Global Constraints

- Follow `CLAUDE.md` and `AGENTS.md`: per-engine SQL, `make sqlc`, `shapes_test.go` pairs, migrations identical-numbered in `migrations/sqlite` and `migrations/pgsql`, ASCII `.sql`, never edit `sqlc/gen`; `make openapi` after any route change; `.env.example` updated for every env var added/removed/changed; contract tests in `internal/app/web/contract` for every new table route (happy path + `probes` for input routes; the TestMain guard requires each route to answer < 400 once).
- No go-pkgz/auth import may remain (`grep -rn go-pkgz/auth` empty; `go mod tidy`).
- Tokens are opaque, ≥ 32 random bytes, base64url, stored only as SHA-256 hex. Prefixes: PAT `wfp_` (unchanged, `pkg/pat`), session `wfs_`, OAuth access `wfo_`, OAuth refresh `wfr_`, secret-request link token `wfx_`.
- Session cookie: name `wf_session`, HttpOnly, SameSite=Lax, Path `/`, Secure when `cfg.GetSecureCookies()`; session lifetime 30 days sliding (extend `expires_at` when `last_used_at` is > 1 day old), max 90 days.
- CSRF: a request authenticated **by the cookie** with method other than GET/HEAD/OPTIONS must carry header `X-Winterflow-Request: 1`, else 403. Bearer/Basic requests are exempt. `web/src/lib/api.ts` sends it on every request.
- `kind` values in `access_tokens`: `session`, `pat`, `oauth`. OAuth tokens (scope `mcp`) are accepted on `/mcp` only, and only while the authorization server is enabled.
- Authorization server enabled iff `WEB_URL` is an https origin with no path, or an http loopback origin (`localhost`, `127.0.0.1`, `[::1]`). Issuer = that origin; resource = `<origin>/mcp`.
- Env vars (document each in `.env.example`): keep `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`; add `AUTH_APPLE_CLIENT_ID`, `AUTH_APPLE_TEAM_ID`, `AUTH_APPLE_KEY_ID`, `AUTH_APPLE_PRIVATE_KEY_PATH`; `AUTH_OIDC_ISSUER`, `AUTH_OIDC_CLIENT_ID`, `AUTH_OIDC_CLIENT_SECRET`, `AUTH_OIDC_NAME` (button label, default "SSO"). Remove `JWT_SECRET` and `AVATARS_STORAGE_PATH`-style go-pkgz-only vars (whatever `GetAvatarsStoragePath` reads) from config, `.env.example`, `scripts/*.sh` and their `*_test.sh`.
- Providers work in standalone and distributed whenever configured (drop the distributed-only restriction in `IsAuthSupported`).
- MCP waits: ≤ 50 s per tool call. `command_results` pruned 24 h after end; `running` rows older than 15 min become `unknown`. Stored result JSON ≤ 1 MiB.
- Secret requests: link valid 24 h unsubmitted; ciphertexts deleted 24 h after submission if unused; rows pruned 7 days after they end; note ≤ 500 bytes per name, message ≤ 2000 bytes, ≤ 32 names.
- `/mcp` per-user limiter: token bucket 10 req/s, burst 30, keyed by user id; 429 past it.
- Commit after each task with a conventional message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A user removed from the org (or deleted) must lose every session, PAT and OAuth grant at once — test in Task 3 (`TestRemoveMemberRevokesTokens`).
- An OAuth `wfo_` token presented to a REST route must get 401, not access — test in Task 4 (`TestOAuthTokenRejectedOnREST`).
- A cookie-authenticated POST without `X-Winterflow-Request` (a cross-site form) must get 403 — test in Task 4 (`TestCookiePostWithoutCSRFHeader`).
- A provider sign-in for an unknown email while registration is closed must not create an account — test in Task 6 (`TestProviderLoginUnknownEmailRegistrationClosed`).
- A secret-request link opened by a member of another org must look exactly like a missing one (404), and `secrets_from` with another org's request id must be refused — tests in Task 13 (`TestSecretRequestOtherOrgNotFound`, `TestSaveAppSecretsFromOtherOrg`).
